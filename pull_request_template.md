## Pull Request Workflow

1. **Branch Cleanly:** Branch off from `main` using descriptive naming of the feature or fix.
2. **Keep PRs Focused:** Small PRs speed up reviews and prevent merge conflicts for our team of 6.
3. **Assign Reviewers:** Request reviews from at least one peer.

## Type of Change
<!-- Check all boxes that apply -->
- [ ] Bug fix (non-breaking change which fixes an issue)
- [ ] New feature (non-breaking change which adds functionality)
- [ ] Breaking change (fix or feature that changes API contracts or core flows)
- [ ] Environment / Configuration change
